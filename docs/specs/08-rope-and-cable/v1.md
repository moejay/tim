# Rope & Cable System — v1 Spec

## Overview

Ropes and cables are flexible connectors that transfer force between parts. They are fundamental to most Rube Goldberg chains.

## Rope Types

### Rope

- **Visual**: thin brown/tan line
- **Cuttable by**: scissors (when closing), hedge trimmers, tin snips
- **Properties**: flexible, stretches slightly under tension

### Steel Cable

- **Visual**: thick silver/gray line
- **Cuttable by**: tin snips ONLY (scissors and hedge trimmers cannot cut it)
- **Properties**: rigid, does not stretch

## Rope Physics

### Tension Model

```
struct RopeSegment {
    start_anchor: AnchorPoint,
    end_anchor: AnchorPoint,
    segments: Vec<Vec2>,       // intermediate points (pulleys, hooks)
    rest_length: f32,          // natural length in pixels
    current_length: f32,       // actual length (computed from segment points)
    is_taut: bool,             // current_length >= rest_length
    rope_type: RopeType,       // Rope or SteelCable
}

enum AnchorPoint {
    Part { part_id: PartId, attach_point: AttachOffset },
    Pulley { part_id: PartId },
    Hook { part_id: PartId },
}
```

### Tension Propagation

- Rope only transmits force when **taut** (current length ≥ rest length)
- Slack rope has no effect
- When taut: force is transmitted along the rope from heavy end to light end
- Force = weight difference between connected objects × gravity

### Rope Routing Through Pulleys

- Rope threads through pulleys to change direction
- Each pulley adds a waypoint to the rope path
- Force direction changes at each pulley (follows rope path)
- Multiple pulleys can create complex force redirection

```
Example: weight pulls rope down → pulley redirects horizontally →
         second pulley redirects up → pulls lever arm upward
```

## Rope Placement

### Placement Workflow
1. Click a part's rope attachment point (shown as a small circle handle)
2. Optionally click pulleys/hooks to add waypoints
3. Click the destination part's rope attachment point
4. Rope is created connecting the two endpoints through all waypoints

### Constraints
- Maximum rope length: 600px total path length
- Minimum rope length: 16px
- Rope cannot pass through solid objects (routes around them if possible, otherwise placement fails)
- Maximum pulleys per rope: 8
- One rope per attachment point (cannot attach multiple ropes to same point)

## Rope Visual

### Rendering
- When slack: rope hangs in a catenary curve (approximated with 3–5 bezier segments)
- When taut: rope renders as straight line segments between waypoints
- Rope sags proportional to slack amount
- Animate rope vibration briefly when tension state changes

### Colors
- Rope: brown (#8B6914)
- Steel Cable: silver (#C0C0C0)

## Cutting Mechanics

### Cut Detection
- Each tick, check if any cutting tool (scissors, hedge trimmers, tin snips) intersects with any rope segment
- Intersection = rope segment passes through the tool's cutting zone

### Cut Effects
- Rope is severed at the cut point
- Both halves become slack immediately
- Connected parts lose tension — heavy objects fall, light objects are released
- Cut rope ends dangle briefly then disappear (0.5s fade)
- Steel cable: only tin snips trigger cutting; scissors and hedge trimmers have no effect

## Rope + Pulley Mechanical Advantage

- Single pulley: redirects force only (no mechanical advantage)
- Block-and-tackle arrangements: possible if multiple ropes/pulleys are configured correctly
- For v1: simplified model — pulleys only redirect, no mechanical advantage calculation

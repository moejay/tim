# Rendering — v1 Spec

## Overview

Dual-engine rendering system: pixel-based (for graphical terminals) and text-based (for any terminal). Both share the same game logic and coordinate system.

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│               Game Logic + Physics                       │
│           (pixel coordinates, renderer-agnostic)         │
├──────────────────────┬──────────────────────────────────┤
│   Pixel Renderer     │        Text Renderer             │
│  image + viuer       │   ratatui + Unicode              │
│  640×360 RgbaImage   │   Terminal cells (responsive)    │
│  Kitty/Sixel/iTerm2  │   Any ANSI terminal              │
└──────────────────────┴──────────────────────────────────┘
```

## Coordinate System

- World coordinates: pixels, origin at top-left (0,0)
- Default playfield: 640×400 pixels
- Y-axis: positive downward (matches screen coordinates)
- All game logic operates in pixel coordinates regardless of renderer

## Renderer Trait

```rust
trait Renderer {
    fn init(&mut self) -> Result<()>;
    fn render_frame(&mut self, state: &GameState) -> Result<()>;
    fn cleanup(&mut self) -> Result<()>;
    fn viewport_size(&self) -> (u32, u32);
}
```

## Mode Detection

```rust
fn detect_mode() -> RenderMode {

    //   TERM=xterm-kitty || KITTY_WINDOW_ID    → Pixel
    //   TERM_PROGRAM=WezTerm                    → Pixel
    //   TERM_PROGRAM=ghostty                    → Pixel
    //   TERM_PROGRAM=iTerm.app                  → Pixel
    //   otherwise                               → Text

```

CLI flags `--pixel` and `--text` override auto-detection.

## Pixel Renderer

### Technology
- Renders to `RgbaImage` (640×360 or higher)
- Displays via `viuer` crate using Kitty graphics protocol, Sixel, or iTerm2 protocol
- Targets 30 FPS display refresh

### Rendering Pipeline
1. Clear framebuffer to background color
2. Render scenery (back layer)
3. Render static parts (walls, floors, platforms)
4. Render ropes and cables
5. Render dynamic parts (balls, boxes, animals)
6. Render effects (explosions, sparks, flames, laser beams)
7. Render scenery (front layer)
8. Render UI overlay (handles, selection highlights)
9. Render HUD (goal text, parts bin, control panel)
10. Display framebuffer via viuer

### Part Rendering

Each part type has:
- Idle sprite (default state)
- Optional animation sprites (spinning gears, burning fuses, walking animals)
- Flip variants (horizontal mirror)
- Size variants (for resizable parts)

### Effects Rendering
| Effect | Technique |
|---|---|
| Explosions | Animated sprite sequence (8 frames) |
| Flames | Particle system (small colored pixels) |
| Sparks | Moving pixel dots with short trails |
| Laser beams | Anti-aliased colored lines with glow |
| Rope | Bezier curve segments |
| Belt | Dashed line between connection points |
| Air/wind | Translucent directional streaks |
| Steam | Rising particle clusters |
| Water drip | Falling pixel dots |

### Colors (Pixel Mode)
- Full 24-bit RGB color
- Anti-aliasing on edges
- Alpha blending for translucent effects
- Background gradient support

## Text Renderer

### Technology
- Uses `ratatui` for terminal UI
- Unicode box-drawing and block characters
- Responsive to terminal size
- Targets any ANSI-compatible terminal

### Character Mapping

```
World pixel coordinates → Terminal cell coordinates

cell_x = world_x / CELL_WIDTH   (CELL_WIDTH = 2 for half-block rendering)
cell_y = world_y / CELL_HEIGHT  (CELL_HEIGHT = 2 for half-block rendering)
```

### Animation in Text Mode
- Use terminal cursor movement and selective redraws
- Animate by redrawing only changed cells
- Ball movement: erase old position, draw at new position
- Explosions: flash sequence of characters (✦ → ✸ → ★ → · → empty)
- Spinning gears: rotate through ⚙ character variants or color cycling

### Color Scheme (Text Mode)
- 256-color palette primary, 16-color fallback
- Background: configurable (default dark blue)
- Parts: category-based coloring for quick identification
- Selection highlight: inverse colors or bright border
- Status: green = running, red = stopped

## Render Loop

```rust
fn game_loop(renderer: &mut dyn Renderer, state: &mut GameState) {
    let target_fps = 30;
    let frame_duration = Duration::from_secs_f64(1.0 / target_fps as f64);

    loop {
        let frame_start = Instant::now();

        // Input
        handle_input(state);

        // Physics (fixed timestep, may run multiple ticks per frame)
        while state.physics_accumulator >= PHYSICS_DT {
            physics_tick(state);
            state.physics_accumulator -= PHYSICS_DT;
        }

        // Render
        renderer.render_frame(state)?;

        // Frame timing
        let elapsed = frame_start.elapsed();
        if elapsed < frame_duration {
            sleep(frame_duration - elapsed);
        }
        state.physics_accumulator += frame_start.elapsed().as_secs_f32();
    }
}
```

## Camera / Viewport

### Scrolling
- Viewport can be smaller than the playfield
- Camera position: `(camera_x, camera_y)` — top-left corner of view
- Scroll via arrow keys or mouse at edges
- Smooth scrolling: lerp camera position over 3–5 frames

### Zoom (Pixel Mode Only)
- Default: 1x (1 world pixel = 1 framebuffer pixel)
- Zoom levels: 0.5x, 1x, 1.5x, 2x
- Zoom center: mouse position or screen center

## Performance

### Pixel Renderer
- Target: 30 FPS minimum
- Optimization: only redraw dirty regions when possible
- Sprite caching: pre-render rotated/flipped variants
- Double buffering via viuer

### Text Renderer
- Target: 30 FPS minimum
- Optimization: diff-based rendering (only redraw changed cells)
- ratatui handles terminal double-buffering
- Minimize cursor movement commands

# Pipe System — v1 Spec

## Overview

Pipes route objects through enclosed channels. Objects enter pipe openings and travel through connected sections, emerging at the other end.

## Pipe Parts

### Large Pipes (Straight Sections)

- **Type**: static part
- **Orientations**: horizontal, vertical
- **Size**: configurable length (32px – 192px), fixed width (24px internal diameter)
- **Openings**: both ends are open by default
- **Connection**: pipe ends within 4px of each other auto-connect

### T-Connectors

- **Type**: static part
- **Size**: 24×24px
- **Openings**: three openings (T-shape)
- **Rotatable**: 4 orientations (0°, 90°, 180°, 270°)
- **Behavior**: objects entering from any opening exit from one of the other two openings based on their trajectory

### Large Curved Pipe

- **Type**: static part
- **Size**: 24×24px at the bend point
- **Openings**: two openings at 90° angle
- **Rotatable**: 4 orientations (0°, 90°, 180°, 270°)
- **Behavior**: redirects object path by 90°

### Accelerator Tubes

- **Type**: static part
- **Size**: 32×24px
- **Programmable**: speed multiplier (1.5x, 2.0x, 3.0x) and direction
- **Behavior**: modifies object velocity as it passes through
- **Direction**: can push objects in a specific direction regardless of entry direction

## Pipe Physics

### Object Transport

```
struct PipeNetwork {
    segments: Vec<PipeSegment>,
    connections: Vec<(PipeEnd, PipeEnd)>,
}

struct PipeSegment {
    part_id: PartId,
    pipe_type: PipeType,
    openings: Vec<PipeOpening>,
}

struct PipeOpening {
    position: Vec2,
    direction: Vec2,  // outward-facing normal
    connected_to: Option<PipeEnd>,
}
```

### Entry Detection
- Object must enter through a pipe opening
- Entry angle must be within 45° of the opening direction
- Object must fit inside pipe diameter (radius < 12px for standard pipes)
- Objects too large to fit are rejected (bounce off pipe exterior)

### Travel Through Pipes
- Object velocity is maintained through pipe (with slight friction reduction: 5%)
- Gravity does NOT affect objects inside pipes
- At T-connectors: object continues in its current direction if possible; if not, takes the perpendicular exit
- At curves: object follows the curve, direction changes 90°
- At accelerator tubes: velocity is multiplied by speed factor

### Exit Behavior
- Object exits from the pipe opening with its pipe-internal velocity
- Gravity resumes affecting the object immediately
- Exit direction matches the pipe opening direction

### Objects That Can Enter Pipes
- All balls (bowling ball may be too large depending on pipe size)
- Cannonball
- Tennis ball, baseball, pinball (all fit easily)
- Mort the Mouse (small enough)
- NOT: cats, Mel, buckets, or any part wider than pipe diameter

## Pipe Connection Rules

- Pipes auto-connect when openings are within 4px and facing each other (opposing directions)
- Disconnected pipe openings act as exits/entries to the pipe network
- A single pipe network can have multiple entry and exit points
- Objects cannot enter sealed (connected) pipe junctions from outside

## Visual Rendering

- Pipe exterior: metallic gray with rivets
- Pipe interior: dark (objects visible through cutaway or transparent section)
- Objects in transit: shown as a moving dot/silhouette through the pipe
- Connection indicators: highlight when pipes are properly connected

## Edge Cases

- Object enters pipe with zero velocity: slowly pushed by gravity toward the lower opening (or stays stuck if horizontal pipe is level)
- Two objects in same pipe section: they push each other (simple 1D collision within pipe)
- Object exits into a wall: object is stopped at the exit point, may fall or bounce depending on surroundings

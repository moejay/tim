# Physics Engine — v1 Spec

## Overview

Deterministic, real-time 2D physics simulation. All simulations run without randomness, ensuring reproducible results given the same initial state.

## Global Parameters

### Gravity

- Slider value: float range `[0.0, 2.0]`, default `1.0`
- `0.0` = zero gravity (objects float until struck)
- `0.1–0.3` = "lunar" / weak gravity
- `1.0` = Earth-normal
- `1.5–2.0` = heavy gravity
- Direction: always downward (positive Y)
- Effect: per-frame downward acceleration = `gravity * object.gravity_factor * BASE_GRAVITY`
- `BASE_GRAVITY` constant: `980.0` pixels/s² (at default scale)

### Atmospheric Pressure

- Slider value: float range `[0.0, 2.0]`, default `1.0`
- Affects: drag coefficient, buoyancy threshold
- Low pressure (`< 0.5`): balloons fall, reduced air resistance
- Normal (`1.0`): standard behavior
- High pressure (`> 1.5`): low-density objects float, increased drag

### Combined Effects

| Gravity | Pressure | Effect |
|---|---|---|
| Weak | Normal | Light objects rise, heavy fall slowly |
| Normal | High | Low-density objects buoyant, movement sluggish |
| Weak | Low | "Moon" — everything falls slowly, no buoyancy |
| Strong | Normal | Everything falls fast, balloons fall |

## Per-Object Physics Properties

Every physics object has these properties:

```
struct PhysicsBody {
    position: Vec2,          // world-space pixels
    velocity: Vec2,          // pixels per second
    mass: f32,               // kg (relative scale)
    elasticity: f32,         // 0.0 = no bounce, 1.0 = perfect bounce, >1.0 = gains energy
    density: f32,            // kg/m³ (relative, for buoyancy calc)
    friction: f32,           // 0.0 = frictionless, 1.0 = maximum grip
    gravity_response: GravityResponse,
    is_static: bool,         // true = immovable (walls, floors)
    collider: Collider,      // shape for collision detection
}

enum GravityResponse {
    AlwaysFalls,             // bowling ball, cannonball, pinball
    Normal,                  // basketball, baseball, tennis ball — falls normal+, rises weak
    Buoyant,                 // balloon — rises normal/weak, falls strong
    ZeroGravity,             // pool ball — floats until struck
    Custom(f32),             // programmable ball — custom gravity factor
}
```

## Simulation Loop

### Tick Rate

- Fixed timestep: `1/60` second (60 Hz physics)
- Simulation runs independently of render framerate
- Accumulator pattern: store leftover time between frames

### Per-Tick Update Order

1. **Apply forces**: gravity, air resistance, buoyancy
2. **Integrate velocity**: `position += velocity * dt`
3. **Broad-phase collision detection**: spatial grid or sweep-and-prune
4. **Narrow-phase collision**: shape-vs-shape tests
5. **Resolve collisions**: impulse-based response
6. **Apply constraints**: ropes, belts, joints
7. **Trigger interactions**: check for state-change events (balloon pop, fuse ignite, etc.)
8. **Update state machines**: animal AI, electrical state, etc.

## Gravity Calculation

```
fn apply_gravity(body: &mut PhysicsBody, gravity: f32, pressure: f32) {
    let buoyancy = pressure * (1.0 / body.density);
    let effective_gravity = match body.gravity_response {
        AlwaysFalls => gravity * BASE_GRAVITY,
        Normal => {
            if gravity < 0.3 {
                -buoyancy * BASE_GRAVITY * 0.3  // rises under weak gravity
            } else {
                gravity * BASE_GRAVITY
            }
        },
        Buoyant => {
            if gravity > 1.3 {
                gravity * BASE_GRAVITY * 0.5    // falls under strong gravity
            } else {
                -buoyancy * BASE_GRAVITY        // rises
            }
        },
        ZeroGravity => 0.0,
        Custom(factor) => gravity * factor * BASE_GRAVITY,
    };
    body.velocity.y += effective_gravity * dt;
}
```

## Collision Detection

### Collider Shapes

- `AABB` — axis-aligned bounding box (walls, floors, boxes)
- `Circle` — radius-based (balls)
- `Polygon` — convex polygon (ramps, inclines, irregular shapes)
- `Segment` — line segment (ropes, belts)

### Collision Response

```
fn resolve_collision(a: &mut PhysicsBody, b: &mut PhysicsBody, contact: &Contact) {
    let restitution = (a.elasticity + b.elasticity) / 2.0;
    let friction = (a.friction + b.friction) / 2.0;

    // Normal impulse (bounce)
    let relative_vel = a.velocity - b.velocity;
    let normal_vel = relative_vel.dot(contact.normal);
    let impulse = -(1.0 + restitution) * normal_vel / (1.0/a.mass + 1.0/b.mass);

    // Apply impulse
    a.velocity += contact.normal * (impulse / a.mass);
    b.velocity -= contact.normal * (impulse / b.mass);

    // Tangential friction
    let tangent = relative_vel - contact.normal * normal_vel;
    if tangent.length() > 0.001 {
        let friction_impulse = -tangent.normalize() * impulse.abs() * friction;
        a.velocity += friction_impulse / a.mass;
        b.velocity -= friction_impulse / b.mass;
    }
}
```

## Air Resistance

```
fn apply_air_resistance(body: &mut PhysicsBody, pressure: f32) {
    let drag = 0.01 * pressure * body.velocity.length();
    body.velocity *= 1.0 - drag * dt;
}
```

## Determinism Requirements

- No floating-point non-determinism: use consistent operation ordering
- No random number generation in physics
- Same initial state + same inputs = identical simulation every time
- Consider fixed-point arithmetic for cross-platform determinism (future)

## Object Rest Detection

- Object is "at rest" when velocity magnitude < `REST_THRESHOLD` (e.g., `0.5` px/s) for `REST_FRAMES` consecutive ticks (e.g., 30)
- Resting objects skip integration until disturbed by external force
- Reduces CPU cost and prevents micro-jitter

## World Bounds

- Objects exiting the world bounds are flagged with exit direction: `OffTop`, `OffBottom`, `OffLeft`, `OffRight`
- Exit events are used by the puzzle goal system
- World bounds are larger than the visible playfield by a margin (e.g., 50px) to allow brief off-screen travel

## Implementation Notes

- Start with simple Euler integration; upgrade to Verlet if stability issues arise
- Spatial partitioning (grid) recommended when object count > 50
- All physics values should be tunable via a config/constants file for balancing

# Puzzle System — v1 Spec

## Overview

The puzzle system manages puzzle definitions, loading, goal evaluation, solution recognition, and player inventory (parts bin).

## Puzzle Definition

```
struct Puzzle {
    id: PuzzleId,
    title: String,
    goal_text: String,               // "Pop the balloon", "Get the ball into the basket"
    difficulty: Difficulty,
    password: String,                // 8-char code to jump to this puzzle
    music_track: Option<String>,

    // World settings
    gravity: f32,                    // 0.0–2.0, default 1.0
    atmospheric_pressure: f32,       // 0.0–2.0, default 1.0
    background_color: Color,

    // Parts
    fixed_parts: Vec<PlacedPart>,    // immovable parts (the pre-built machine)
    player_parts: Vec<PartInventory>, // parts the player can place

    // Goals
    win_conditions: Vec<WinCondition>,

    // Optional
    hints: Vec<Hint>,
    scenery: Vec<SceneryItem>,
    solution: Option<Vec<PlacedPart>>, // Professor Tim's solution
}

enum Difficulty {
    Tutorial,
    Easy,
    Medium,
    Hard,
    Expert,  // "Really Hard"
}

struct PlacedPart {
    kind: PartKind,
    position: Vec2,
    flip_state: FlipState,
    size: Option<Vec2>,              // for resizable parts
    program: HashMap<String, ProgramValue>,  // programmable settings
    rotation: u8,                    // 0, 90, 180, 270 for rotatable parts
}

struct PartInventory {
    kind: PartKind,
    quantity: u32,                   // how many the player has
}

struct Hint {
    position: Vec2,
    text: String,
    icon: HintIcon,                  // pointing finger
}

struct SceneryItem {
    kind: SceneryKind,
    position: Vec2,
    layer: SceneryLayer,             // Front or Back
}

enum SceneryLayer {
    Front,  // renders in front of parts
    Back,   // renders behind parts
}
```

## Win Conditions

### Condition Types

```
enum WinCondition {
    // Object destination
    ObjectInContainer {
        object: PartSelector,
        container: PartSelector,
    },
    ObjectAtPosition {
        object: PartSelector,
        target: AABB,               // target rectangle
    },
    ObjectExitedWorld {
        object: PartSelector,
        direction: ExitDirection,    // OffTop, OffBottom, OffLeft, OffRight, OffScreen (any)
    },

    // State change
    BalloonPopped { balloon: PartSelector },
    AllBalloonsPopped,
    CandleLit { candle: PartSelector },
    AllCandlesLit,
    DynamiteExploded { dynamite: PartSelector },
    AllDynamiteExploded,
    RocketLaunched { rocket: PartSelector },
    CannonFired { cannon: PartSelector },
    GunFired { gun: PartSelector },
    AllGunsFired,
    FanTurnedOn { fan: PartSelector },
    AllFansTurnedOn,
    FishbowlBroken { fishbowl: PartSelector },
    GearSpinning { gear: PartSelector },
    WindmillSpinning { windmill: PartSelector },
    TeapotBoiling { teapot: PartSelector },
    JackInTheBoxOpened { jack: PartSelector },

    // Creature goals
    MelEnteredHouse { mel: PartSelector, house: PartSelector },
    MouseReachedHole { mouse: PartSelector, hole: PartSelector },
    CatCaughtMouse { cat: PartSelector, mouse: PartSelector },
    AnimalEatenByAlligator { animal: PartSelector, alligator: PartSelector },
    CatTrapped { cat: PartSelector },
    MouseTrapped { mouse: PartSelector },
    ObjectVacuumed { object: PartSelector },
    MonkeyRiding { mandrill: PartSelector },
    AllMiceInWheels,

    // Prevention (must NOT happen)
    PreventBalloonPop { balloon: PartSelector },
    PreventFishbowlBreak { fishbowl: PartSelector },
    PreventMouseEaten { mouse: PartSelector },

    // Compound
    AllOf(Vec<WinCondition>),        // all must be true simultaneously
    AnyOf(Vec<WinCondition>),        // at least one must be true
}

enum PartSelector {
    ById(PartId),                    // specific part instance
    ByKind(PartKind),                // any part of this type
    All(PartKind),                   // all parts of this type
    Tagged(String),                  // custom tag for level editor
}

enum ExitDirection {
    OffTop,
    OffBottom,
    OffLeft,
    OffRight,
    OffScreen,  // any direction
}
```

### Prevention Conditions

Prevention conditions work differently: the puzzle is **failed** if the prevented event occurs.

```
struct PuzzleState {
    status: PuzzleStatus,
    failed_prevention: Option<WinCondition>,  // which prevention condition was violated
}

enum PuzzleStatus {
    Building,      // player is placing parts
    Running,       // simulation is active
    Won,           // all win conditions met
    Failed,        // prevention condition violated
    Stopped,       // player stopped simulation
}
```

### Goal Evaluation

Each tick during simulation:

```
fn evaluate_goals(puzzle: &Puzzle, world: &World, events: &[GameEvent]) -> PuzzleStatus {
    // 1. Check prevention conditions first
    for condition in &puzzle.win_conditions {
        if let WinCondition::Prevent* = condition {
            if prevention_violated(condition, events) {
                return PuzzleStatus::Failed;
            }
        }
    }

    // 2. Check positive conditions
    let all_met = puzzle.win_conditions.iter()
        .filter(|c| !is_prevention(c))
        .all(|c| condition_met(c, world, events));

    if all_met {
        PuzzleStatus::Won
    } else {
        PuzzleStatus::Running
    }
}
```

### Timing

- Goals are evaluated continuously during simulation
- Some goals require state persistence (e.g., "object at rest in position" needs the object to stay there for ~1 second)
- Prevention conditions are checked against the event stream (any frame the event occurs = failure)

## Parts Bin (Player Inventory)

```
struct PartsBin {
    available: Vec<PartInventory>,
    placed: Vec<PartId>,            // parts currently on the playfield
}

impl PartsBin {
    fn take_part(&mut self, kind: PartKind) -> Option<()>;    // decrement quantity
    fn return_part(&mut self, kind: PartKind);                 // increment quantity
    fn quantity(&self, kind: PartKind) -> u32;
    fn is_empty(&self) -> bool;
}
```

### Parts Bin Rules
- Player can only place parts available in the bin
- Quantity decrements when placed, increments when returned
- In Puzzle Play: limited quantities per the puzzle definition
- Some puzzles include decoy/extra parts the player doesn't need
- Not all parts need to be used to solve the puzzle

## Solution Display

- Professor Tim's solution is stored as a list of `PlacedPart` entries
- "Show Solution" replaces the player's parts with the solution parts
- Player can toggle back to their own attempt
- Solution parts are visually distinct (e.g., semi-transparent or highlighted)

## Puzzle Progression

- Puzzles within each difficulty tier can be played in any order
- Completing all puzzles in a tier unlocks the next tier
- Each solved puzzle reveals a password for sharing/jumping
- Progress is tracked per player sign-in name
